My only complain, albeit only faint and doesn't change the structure that much, is the unused counter.razor and weather.razor, and home.razor.bak files in the pages.
- **Naming of files/folders** 5/5

- **Code organization**  3.5/5
    - While the code is lengthy due to the amount of features and design this website has, it is the names of the codes made it easier to understand what is inside. The programmer also knows when to put the code inside the html and when to put it in @code{}. My only complaint is that the html design for the pages could've been moved into a css file as some of the classes in the div seem to use similar codes to each other like the background colour and such.
- **Commit names/messages**  5/5
    - The naming conventions are spot on and understandable in the commit timeline. It shows what type of commit it is and what is being committed. It is short, simple and direct to the point with the commit messages.
- **Overall repository organization and cleanliness**  4/5
    - Overall it has good organization and project structure. It's clean, the naming conventions live up to its name, and it's simple to understand what each page or commit is talking about. Of course, there are the drawbacks such as the unneccesary files that were yet to be deleted and the structure inside the codes.
